# 通知解析规则

自动读取是产品的核心：用户不用打开群、不用点任何按钮，App 靠通知栏里的内容自动出卡。真机上微信、QQ 的通知有几种形状，之前只处理了最简单的一种。纯逻辑放在 `com.nopalou.NotifParser`（不依赖 Android），`NotifListener` 只负责把通知里的字段取出来交给它。

## 接口

```java
static List<NotifParser.Parsed> parse(String title, String text,
        String[] msgSenders, String[] msgTexts, long[] msgTimes, boolean isSummary)
```

- title：通知标题（群聊时是群名），可为 null 或空。
- text：通知正文，可为 null。
- msgSenders、msgTexts、msgTimes：通知里的多条消息（MessagingStyle），三个数组同长；没有就传 null 或空数组。
- isSummary：这是不是系统生成的分组汇总通知。
- Parsed 有三个公开字段：String sender、String body、long time（毫秒，未知为 0）。
- 返回按消息先后顺序排列的列表，没有可用消息时返回空列表，不返回 null。

## 规则（按顺序）

1. isSummary 为真，返回空列表。
2. 多条消息：msgTexts 非空时，对每一条：正文先做清洗（见第 4 条），清洗后为空就跳过；发送者取 msgSenders[i] 去首尾空白，为空或 null 时用"群友"；时间取 msgTimes[i]（数组缺失或越界取 0）。按原顺序返回。
3. 单条消息：没有多条消息时用 text。先清洗，为空则返回空列表。再用 NotifFilter.senderSeparator(清洗后的文本)（同包静态方法，已有）找发送者分隔符：找到时，发送者是分隔符之前的部分（去空白），正文是之后的部分（去空白）；找不到时，发送者在 title 为空时是"群消息"，否则是"群友"，正文是整段文本。分割后正文为空则返回空列表。时间为 0。
4. 清洗：
   - 去掉开头的折叠计数，形如 `[3条]`、`[12条]`（半角方括号里是数字加"条"，后面可有空白），只去开头一次。
   - 去掉首尾空白。
   - 清洗后整段只是占位符则视为空：`[图片]`、`[表情]`、`[语音]`、`[视频]`、`[文件]`、`[动画表情]`、`[位置]`、`[链接]`。
   - 清洗后整段是纯计数通知则视为空，匹配 `^(你有)?\d+条新?消息$`，例如"3条新消息""你有5条消息"。
   - 正文里夹带占位符不处理，例如"[图片] 作业在这里"保持原样。
5. 任何步骤都不能抛异常；title、text、数组都可能是 null。
