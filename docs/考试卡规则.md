# 考试/日程卡规则（2026-11-04 定，Java 与 Python 两版行为一致）

## 什么时候出卡
同时满足下面 4 条，出一张 kind = `"exam"` 的卡（不是 todo，也不再另出 todo 卡）：
1. 提到考试：含 考试 / 测验 / 小测 / 笔试 / 机考 / 答辩 / 期中考 / 期末考 之一；
   单独的"期中""期末"只有在消息里**没有**交/提交/上传这类提交动词时才算（"期末大作业周五前交"仍是普通待办）。
2. 有具体时间：`parseDeadline`（Python 为对应函数）解析成功。"时间另行通知""近期考试"这类不出卡。
3. 发送者可信：名字含 老师/辅导员/班长/课代表/社长/主任（即现有 TEACHER_HINTS），或消息带 @所有人 / @全体。
4. 不是提问、不是第一人称：消息不含 吗 / ？ / ? / 呢 / 什么 / 几点 / 哪，且不以 我 / 俺 / 咱们 开头。

判断放在撤销/更正和接龙之后、按分类标签分流之前，所以分类器判成"通知"或"闲聊"也照样出卡（Java 原来会把"通知类"直接丢掉）。

## 卡上写什么
- `title`：非空，包含消息里命中的考试词（如"期中考试""答辩"）。
- `deadline` / `deadlineText`：考试时间（和 parseDeadline 结果一致），`needsConfirm = false`（低置信度时为 true）。
- `place`：沿用 findPlace 的结果（如"教三 201"），没有就留空。
- `bring`（新字段，字符串）：消息里"带 / 携带 / 自备"后面到下一个标点（，。；！\n）之间的内容，如"带学生证和2B铅笔" → `学生证和2B铅笔`；没有就留空。
- groupId / groupName / sender / sourceId / sourceText / sourceTs 和 todo 卡一样填。
- Java 的 saveState / loadState 要保存并恢复 kind 和 bring。

## 改时间、取消
- 可信发送者或原发送者发改期、取消通知时，用考试名称在同群卡片原文中匹配。只有唯一匹配才会更新或取消。群里有两场期中考试时，应写明「数据库期中考试」等完整名称。
- 改期同时提到旧时间和新时间时，解析「改到」「改为」「推迟到」等词之后的新时间。Java 卡片详情可查看最近一次成功更新的更正原文。
- 提问、第一人称陈述、来源不可信、找不到所指考试或存在多个匹配时，保留原有卡片。取消通知仅移除明确匹配的考试卡。

## 不出卡的例子
- 同学："周五考什么" / "期末考试几点啊？" / "我周五上午考试" / "听说周三考试"（同学不可信）
- 老师："期末考试时间另行通知"（没有具体时间）

## 补充规则（2026-11-04）
- 地点：除了"地点xxx"，"教一/教二/教三…/教学楼/实验楼/理科楼/综合楼 + 房号"这种写法也算地点，如"教二305""实验楼305""教一102"，整段房号写进 place。
- 准备类消息不出考试卡：消息含 看完 / 看一下 / 看看 / 复习好 / 预习 / 背完 之一时，说的是"考前把资料看完"，不是考试通知，按普通待办走（如"期中考试范围已发在群文件，周五9点前看完"）。带"范围"但没有这些词的（如"期中考试周三9点，范围第一到五章"）仍然出考试卡。
