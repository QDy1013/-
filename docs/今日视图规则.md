# 今日视图规则（人性化改版）

目的：学生打开 App，第一眼就知道"今天要做什么、哪件最急"，而不是看一串日期和"处理了多少条消息"的统计。

纯逻辑放在 `com.nopalou.TodayView`（不依赖 Android），界面只负责显示。时间都按手机本地时区的自然日算。

## 1. 分组 `bucket(deadline, needsConfirm, done, now)`

按顺序判断，命中就返回：

| 条件 | 返回 |
|---|---|
| done 为真 | `已完成` |
| needsConfirm 为真，或 deadline == 0 | `待确认` |
| deadline <= now | `已过期` |
| deadline 与 now 同一天 | `今天` |
| deadline 是 now 的下一天 | `明天` |
| 与 now 相隔 2～7 天（按自然日） | `这几天` |
| 相隔超过 7 天 | `更晚` |

分组的显示顺序固定：`今天`、`明天`、`这几天`、`更晚`、`待确认`、`已过期`、`已完成`。`TodayView.ORDER` 是这个顺序的字符串数组。

## 2. 倒计时文字 `countdown(deadline, now)`

- deadline == 0：`时间待确认`
- 已过期：差不到 1 小时 → `刚过期`；不到 24 小时 → `已过期N小时`（N 向下取整）；否则 `已过期N天`（N 向下取整）
- 未过期：
  - 差不到 60 分钟 → `还剩N分钟`（N 向下取整，至少 1）
  - 差不到 24 小时 → `还剩N小时`（N 向下取整）
  - 否则按自然日相隔：1 天 → `明天 HH:mm`，2 天 → `后天 HH:mm`，更久 → `N天后`（N 为相隔自然日数）

## 3. 紧急程度 `urgency(deadline, needsConfirm, done, now)`

返回整数，界面用它选颜色：
- done 或 needsConfirm 或 deadline == 0 → 0
- 已过期 → 3
- 差不超过 3 小时 → 2
- 差不超过 24 小时 → 1
- 其他 → 0

## 4. 顶部一句话 `summary(cards, now)`

只统计 `done` 为假的卡片。

- 全部分组都是 0 张（没有任何未完成的卡）→ `目前没有待办`
- 否则把下面的片段用 ` · ` 连接，按顺序：
  - 今天有 n 张 → `今天 n 件`；今天没有 → `今天没有截止`
  - 明天有 n 张 → `明天 n 件`（0 张不写）
  - 已过期 n 张 → `已过期 n 件`（0 张不写）
  - 待确认 n 张 → `待确认 n 件`（0 张不写）
- "这几天"和"更晚"的卡不写进这一句。
- 分组按第 1 节的 `bucket` 算。
