# 三轮功能检查记录

> 2026-11-03 审查与修复后，本文中的数字已过时，以 README.md 和 docs/修复进度.md 为准。

每一轮都不是"看一眼说没问题"，而是跑脚本、看输出、改代码，再跑一遍。

## 第一轮：单元与端到端

**跑什么**
- `eval/run_hardset.py`：60 条手写分布外样本
- `android/test/EngineTest.java`：19 项断言，JVM 上直接驱动端侧引擎

**查出并修掉的问题**

| # | 问题 | 怎么发现的 | 修法 | 修前 → 修后 |
|---|---|---|---|---|
| 1 | 接龙黄金标签和名单对不上 | 接龙召回只有 21.8%，抽查发现"标记为没接、名单里却有我" | 生成器候选池排除本人 | 21.8% → 88.4% |
| 2 | 训练时用了"未来"的回复潮特征 | 四分类 100% 但线上召回 71%，特征在推理时永远为 0 | 训练和推理都按 0 处理，回复潮改由重打分兑现 | 召回 71% → 84.6% |
| 3 | 发送者是否"常发通知"线上恒为 0 | 对比训练/推理的统计口径 | 线上用模型预测标签在线更新统计 | 精度 78.8% → 86.7% |
| 4 | ②类通知被做成待办 | 误报样例里全是"调课通知…" | ②类改出信息卡，不占待办位 | 精度 78.8% → 86.7% |
| 5 | 安卓端 `8 点` 解析失败（正则不容空格） | EngineTest 时间用例 5 连错 | 正则加 `\s*` | 时间 4/10 → 10/10 |
| 6 | "上课前"没有默认时刻 | 同上 | 补早八默认值 | — |
| 7 | 已接的接龙继续往下走成待办 | 误报里出现带本人名字的接龙 | 接龙分支处理完立即返回 | 精度 95.5% |
| 8 | 第一人称陈述被当待办 | "我明天把实验报告交了"出卡 | 硬规则：第一人称 + 动作词 ⇒ 讨论 | — |
| 9 | 回复潮把反问句升成待办 | 误报"第3组下周展示是不是要提前准备" | 升卡加护栏：第一人称/反问/停课类不升 | — |
| 10 | 事项标题残留"三上课前" | 卡片标题不对 | 清洗时间片段后再取短语 | "三上课前交读书报告" → "交读书报告" |
| 11 | `sender=None` 直接崩 | 留出集评测抛 TypeError | 空值兜底 | 崩溃 → 正常 |

**结果**：19/19 断言通过；手写集分类 59/59、待办 23/23、时间 20/20、接龙 5/5。

## 第二轮：集成与静态检查

**跑什么**
- `bash android/build.sh`（aapt2 → javac → d8 → zipalign → apksigner）
- `aapt dump badging` / `aapt2 dump xmltree`
- `apksigner verify --print-certs`
- `eval/run_eval.py` 全量回归

**查出并修掉的问题**

| # | 问题 | 修法 |
|---|---|---|
| 1 | `apksigner` 不认 `--storepass`（那是 jarsigner 的参数） | 改 `--ks-pass pass:android --key-pass pass:android` |
| 2 | Git Bash 里没有 `zip`，dex 塞不进 APK | 用 Python `zipfile` 追加 `classes.dex` |
| 3 | `javac @sources.txt` 在 Windows 下静默失败 | 改数组传参，并把 javac 日志落盘 |
| 4 | 模型权重在 Python 与安卓端不同步 | 训练后统一导出 `model.tsv` 到 `app/assets` |

**结果（全部通过）**
- `package=com.nopalou`，`minSdk 24`，`targetSdk 34`，启动 Activity 正常
- `NotifListener` 带 `BIND_NOTIFICATION_LISTENER_SERVICE`，`ReadService` 带 `BIND_ACCESSIBILITY_SERVICE`
- 签名 `CN=Android Debug` 有效（v1+v2）
- 回放器带 `POST_NOTIFICATIONS`
- 产物：`nopalou.apk` 48 KB，`replay.apk` 20 KB
- Python 回归：召回 94.7 / 精确 95.5 / F1 95.1，与修改前一致

## 第三轮：场景走查（对着方案书逐节过）

| 场景 | 期望 | 实际 |
|---|---|---|
| 群里 272 条消息涌入 | 噪声被丢掉，不占内存 | 丢弃 74 条，进模型 4 条 |
| 老师发作业通知 + 30 条"收到" | 出待办卡，截止时间是绝对时间 | 「交实验报告」周一 22:00 学习通 |
| 班长发接龙，名单里没我 | 提醒"你还没接" | 接龙卡，标注 5 人已接、名单没你 |
| 组员 @我做 PPT | 出卡并标为与我相关 | 「@李承宇 展示 PPT…」周五 18:00 |
| 另一门课交读书报告 | 出卡 | 「交读书报告」11/11 08:00 邮箱 |
| 老师说"更正一下，改到下周一 22 点" | 更新原卡，不新建 | 原卡被更新，`已更新` 标记 |
| "我明天把实验报告交了" | 不出卡 | 不出卡 |
| "明天一起吃饭？" / "明天停课" | 不出卡 | 不出卡 |
| "尽快交一下材料" | 出卡但标"待确认" | 出卡，截止显示"待确认" |

**查出并修掉的问题**
1. 首次进入没给通知权限时界面全空，用户不知道要授权 → 加首启引导弹窗
2. 演示脚本原来用绝对日期（11 月 7 日），换一天演示就全过期 → 全部改相对表达（明晚/周五/下周三）
3. "作业截止改到下周一"单条无法判定（本来就是更新行为）→ 手写集里改成两条消息的流式用例
