# 多校本科课表测试（v0.18）

本版本为三校同学分发测试准备，无需 USB、电脑或技术基础。新学校标记为“测试中”，不能据模拟测试声称三校账号已实际导入成功。西工大的账号密码一键导入和周课表交互已通过此前真机测试。

## 给测试同学

安装“楼外·多校测试” → 选自己的学校 → 输入页面提示的账号密码 → 点“一键导入”。校方要求验证码时本人完成，之后自动继续。

成功后核对是不是自己的课表，课程、时间、地点是否正确，试一下左右换周和课程详情。失败点“反馈问题”，通过系统分享选微信或QQ发给邀请测试的人。不用找日志，不需要把密码发给开发者。

独立分发包直接进入课表登录，不展示消息通知权限和保活引导，仅申请网络权限；应用 ID 为 `com.nopalou.timetabletest`，名称“楼外·多校测试”，与原版以及 `com.nopalou.preview` 独立保存数据。

## 首轮适配范围

公共适配器可识别明确的账号、密码和唯一登录按钮，点击校方原按钮，保留其加密、验证码与二次验证。只在选中学校允许的 HTTPS 身份范围填入凭据，表单目标须为同源，不重复提交。校内导航仅选择明确的学生登录、统一认证、教务系统、个人课表等只读入口。

课表解析支持具有课程名、周次、星期、节次等明确表头的结构化表格，包括 rowspan、连续/非连续周、单双周、开始节与节数或结束节、地点和教师。不同学校的未知网格或 JSON 格式尚未逐校确认，遇到未知结构会提示反馈，不能假装导入成功。开学日期必须来自明确页面字段，缺失则不保存，不以今天或固定日期填补。

学校、登录适配、解析及存档信息已拆分。新学校课表通过同一规范化模型与周视图，不改变西工大已保存课表的格式；失败不覆盖旧课表。

## 反馈与隐私

“反馈问题”通过 Android 系统分享，只在用户自行选择接收方后发送。内容包括学校、固定错误说明、版本、手机型号与系统版本，以及自动生成的页面结构：不含查询串的安全路由、输入框类型和字段名、已知静态表头、表格行数、是否存在学期日期等。

反馈不读取或附上账号、密码、验证码输入值，不附带 Cookie、完整网址查询参数、课程名、教师名、地点或完整网页。路由中的未知部分统一替换，属性名中的长串或疑似数字账号替换为占位符。对话框或校方页面不截图上传。没有遥测或反馈中转服务器。

## 验证与构建

- Node：西工大登录13项、读取30项、公共适配27项。
- Java：日期、存档、重叠布局、旧存档兼容和学校域名边界29项。
- 分发包已通过 SDK 34 编译和签名验证，只含 INTERNET 权限。
- 已在手机检查首次打开直接显示两项凭据输入、三校选择、陕师大凭据说明，以及失败时的反馈按钮和系统分享入口；未使用三校的真实账号登录。

构建：`python android/build.py --sdk <SDK路径> --timetable-test`，产物 `nopalou-timetable-test.apk`。`--preview` 仍生成原来的完整独立预览包。D8 通过单个 classes.jar 接收编译结果，避免 Windows 批处理参数长度限制。

后续根据三校同学反馈补齐具体页面与接口，逐校验证账号密码一键导入、课程完整性、周次/作息、重启恢复和失败保留旧表；在此之前保留“测试中”标记。
