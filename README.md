# 「不爬楼」端侧群消息待办助手 — 实现版

方案书对应的可运行实现。不是原型图，是真能跑的代码：合成数据 → 三级流水线 → 评测 → 安卓 App。

```
nopalou/
├── data/synthesize.py      合成群聊数据（2.7 万条，含难例、接龙、变更、易混负例）
├── engine/
│   ├── timeparse.py        中文时间归一化（规则优先，解析不了就返回"待确认"）
│   ├── features.py         8 维手工特征 + 字符 2-gram（训练/端侧同一套定义）
│   ├── extract.py          第三级结构化抽取（事项/截止/渠道/地点）
│   ├── jielong.py          接龙检测与"你还没接"判断
│   ├── pipeline.py         三级编排 + 回复潮重打分 + 变更撤销 + 个人档案
│   └── model.json/.tsv     分类器权重（JSON 供 Python，TSV 供安卓端）
├── eval/
│   ├── train.py            训练第二级分类器，导出端侧权重
│   ├── run_eval.py         留出集评测 + 对比实验 + 消融实验
│   ├── run_java_eval.py    用 APK 的 Java 引擎复跑同一留出集，对照 Python 版
│   ├── hardset.jsonl       手写分布外测试集（60 条）
│   ├── run_hardset.py      分布外评测
│   ├── time_cases.tsv      Python/Java 共用的时间解析用例
│   └── test_*.py           6 个 Python 验收用例：时间解析、撤销规则、评测修正、考试卡（两个）、去重与排序
└── android/
    ├── app/                主 App（通知监听 + 无障碍读屏 + 卡片 + 日历）
    ├── replay/             消息回放器（演示用，重放 272 条通知）
    ├── test/               Java 自测：EngineTest（19 项）+ Step3~6、Step8~11 验收用例，JVM 直接跑
    ├── build.py            Windows / Linux 通用构建入口（Android SDK + JDK）
    └── build/*.apk         产物

(另有 docs/：审查意见、修复进度、考试卡规则、方案书对照、检查记录)
```

## 怎么跑

```bash
# 1. 造数据
python3 data/synthesize.py --days 190

# 2. 训练第二级分类器（顺带打印留出集混淆矩阵）
python3 eval/train.py

# 3. 评测：留出集 + 对比 + 消融
python3 eval/run_eval.py
python3 eval/run_hardset.py
# 3b. Java / Python 留出集对照（需要 JDK 8+，并在可写目录运行）
python3 eval/run_java_eval.py --out java-comparison.json
# 可选：附上 Java 引擎逐条处理耗时
python3 eval/run_java_eval.py --timing --out java-timing.json

# 4. 端到端自测（不需要模拟器/手机）
cd android && javac -d build/test app/src/com/nopalou/Engine.java test/EngineTest.java
java -cp build/test com.nopalou.EngineTest app/assets replay/assets/messages.txt

# 4b. Python 验收用例（每个都是独立脚本，失败时退出码非 0）
for t in test_time_cases test_revoke_rules test_eval_fixes test_exam_cards test_exam_edge test_dedup_rank; do python3 -I eval/$t.py; done

# 5. 构建 APK（JDK 17+、Python 3.9+、Android SDK Platform 34 和 Build Tools 34.0.0）
# 设置 ANDROID_HOME，或加 --sdk <SDK 目录>
python android/build.py
```

## 实测指标

本节的基线、消融和手写集结果均来自 Python 版（`engine/`）。APK 使用的 Java 引擎结果见下方对照。

**合成留出集**（8086 条，按时间切分，最后 30% 作留出集；但留出集 82.3% 的句子在训练集出现过，见下）

| 方案 | 召回 | 精确 | F1 | 时间准确 | 接龙召回 | 接龙精确 | 变更处理 |
|---|---|---|---|---|---|---|---|
| 本方案（三级流水线） | 97.8% | 95.9% | 96.8% | 92.3% | 100% | 100% | 80.8% |
| 基线：只用关键词规则 | 88.5% | 89.1% | 88.8% | 100% | — | — | — |
| 消融：去掉第一级规则 | 80.1% | 98.6% | 88.4% | 91.5% | 100% | 100% | 80.8% |
| 消融：去掉回复潮 | 97.8% | 96.2% | 97.0% | 92.3% | 100% | 100% | 80.8% |
| 消融：去掉个人档案 | 97.8% | 95.9% | 96.8% | 92.3% | 100% | 100% | 80.8% |

**只看没见过的句子**（同一留出集里剔除训练集中出现过的句子）：召回 97.5%。精确 100%（以及由它算出的 F1）不算成绩——没见过的句子里几乎没有干扰句，这个分母太干净。

**Java / Python 引擎对照**（同一批 8086 条留出消息、同一演示档案，分别加载 APK 和 Python 所带的模型权重）

| 引擎 | 待办召回 | 待办精确 | 截止时间准确 | 未见过句子的待办召回 | 接龙召回 | 接龙精确 |
|---|---|---|---|---|---|---|
| Java（APK 引擎） | 97.51% | 95.91% | 93.19% | 97.17% | 100% | 100% |
| Python | 97.78% | 95.92% | 92.28% | 97.53% | 100% | 100% |

接龙按消息到达时是否生成或刷新提醒计分，并计入非接龙消息上的误报。两端都命中 43 条应提醒的消息，均无误报。截止时间准确率沿用 Python 评测口径，只统计成功出卡且有标准截止时间的待办。此对照在 JVM 上直接驱动 APK 使用的引擎，真机通知读取和界面需要单独验证。

**手写分布外集**（60 条）：原来报的 23/23 不成立，发送者当时是按答案设的。现在改报两组极端假设：

| 发送者假设 | 召回 | 精确 |
|---|---|---|
| 全设老师 | 100% | 88.5% |
| 全设学生 | 73.9% | 100% |

**端到端自测**：EngineTest 19 项断言全过，另有 Step 系列验收用例（时间解析、撤销、接龙、通知过滤、考试卡、去重排序等）。演示脚本 272 条消息 → 噪声丢 74 条 → 进模型 4 条 → 4 张卡片：

```
[todo]    交实验报告        周一 22:00  学习通  数据库系统（被"更正"改过时间）
[jielong] 接龙：体测报名（你还没接）  周五 18:00  群接龙
[todo]    @李承宇 展示 PPT…  周五 18:00          挑战杯小组群
[todo]    交读书报告        11 月 11 日 08:00  邮箱  计算机网络
```

## 功能清单

- 群消息待办卡：从群消息里挑出要你做的事，写明截止时间、渠道、地点；时间说不清就标"待确认"，不乱猜。
- 接龙提醒：群里有接龙而名单里没有你，出"你还没接"的卡；你接了就消掉，同群同标题只留一张。
- 考试/日程卡：老师、班长等发的、提到考试/测验/答辩并带具体时间的消息，出一张单独的卡，写时间、地点和要带的东西；"考试改到下周三"会改原卡，"周五考什么"这类提问不出卡（规则见 `docs/考试卡规则.md`）。
- 更正和撤销只认可信的人（老师、班长等），并且要指得清是哪一条，不会因为谁说一句"取消"就删卡。
- 同群有多场考试时，改期或取消须唯一匹配考试名称。卡片详情可回看最近一次更正原文。确认回复只会影响同群十分钟内的候选待办。
- 重复推送去重：同一群里 30 分钟内原样重复的消息只出一张卡。
- 卡片可以标"已完成"（划线变淡、排到最后），过期的卡排在没过期的后面。
- 读当前群：点按钮后 6 秒内切到群聊。回到主 App 后填群名并勾选需要的文字，再确认导入。预览暂存在内存，5 分钟后无法提交。
- 加入日历：用系统日历，不写群消息原文；没有时间的卡不会乱填时间。
- 我的档案：首次启动填姓名、班级、课程，用来判断消息和你有没有关系。
- 通知读取状态：主界面显示"通知读取：已连接/未连接"，未连接时点一下有引导。
- 离线演示：主 App 内直接体验作业、考试、接龙与更正。样例卡片使用独立引擎，不写入日常卡片列表。
- 粘贴群消息：免打扰群或通知缺失时，可以手动填群名并粘贴一条完整消息。粘贴旧消息时可选原发送时间，用来解释「明天」等相对日期。同名的手动群和通知群各自处理。
- 修正卡片：修改事项标题和时间，或把时间标为待确认。卡片保留原文和识别标题，便于追溯和继续匹配群里的更正。
- 搜索和筛选：按标题、群名、发送者、渠道、地点查找，多个词可联合匹配。可筛选未完成、已过期和已完成，长列表可继续显示更多。
- 考试标题与时间分开显示。超出范围的钟点会标为无法解析，避免改成另一个时间。手动清空待办时，同时清理本次运行中的近期识别上下文和待读屏预览。
- 到期提醒默认关闭。用户开启并允许通知后，已确认时间的未完成事项在到期前两小时进入提醒窗口。通知栏只显示通用提示，实际送达时间由系统安排。改期、完成、清空或重启后会重算提醒。
- 没有申请网络权限，消息不出手机。

## 已知限制

- 部分国产手机（如 vivo）重启后可能拒绝连接通知监听，这是系统对非商店安装 App 的限制，需要在手机设置里允许自启动和后台运行；主界面的"通知读取"状态会如实显示。
- "读当前群"读取的是可见文字节点，系统通常不提供发送者信息。可用「粘贴群消息」补录完整正文、发送者和发送时间。
- Java 与 Python 的留出集对照使用合成数据和固定演示档案，覆盖从消息进入引擎到卡片输出的部分。
- 合成数据偏模板化，真实群聊上的表现要靠真人的群来测。
- 方案书里的第三级端侧大模型、第二级小 BERT 没有接入，分别用规则抽取和逻辑回归代替（见下面"没做完的部分"）。

## 这套数字的可信度

必须说清楚三件事，否则上面的表会被误读：

1. **合成数据是模板生成的**。模板化数据上关键词基线就能到 88%，所以"分布内 97.8%"只能说明流水线自洽，不能代表真实群聊。
2. **留出集不干净**。按时间切分的留出集里，82.3% 的句子在训练集出现过（待办 21%、通知 98%、讨论和闲聊 100%），所以"分布内"数字偏乐观。只看没见过的待办句，召回 97.5%。按句子剔除也切不出干净的留出集：剔完以后训练集里"讨论""闲聊"一条不剩，这份合成数据做不出"全是没见过的句子"的留出集，要测泛化只能补一批新写法的数据。
3. **手写集原来的 23/23 是标签泄漏**。发送者原来是按答案设的，等于把答案写进了特征。修正后改报两组极端假设：全设老师，召回 100% 但精确 88.5%；全设学生，精确 100% 但召回 73.9%。真实准确率要靠方案书 8.2 说的真实群聊测试集，那需要真人的群。
4. **消融**。回复潮：原来的消融开关写错了（没有真正关掉 `_track_ack`），修正后回复潮只提升 1 张卡，且那张是误报（精确 95.9% → 96.2%），没有正向增益。个人档案：去掉后指标与全量完全相同，说明合成数据里档案筛不到边。这两个机制的真实增益都要靠真实数据才能测出来。回复潮的重打分逻辑在 `pipeline.py::_track_ack/_promote`，有护栏（第一人称、反问、停课类不升）。
5. **撤销/更正规则和课程群规则两版已对齐**（`eval/test_revoke_rules.py` 与 `android/test/Step4Test.java` 同一组场景）。
6. **更正处理准确率 80.8% 偏低**，主要是合成数据的问题：204 条更正里有 59 条（29%）是同学或空发送者发出的，数据却当作有效更正；新规则按设计不接受同学改老师定的截止时间。召回从 94.5% 升到 97.8%，是因为课程群里老师的通知不再被丢弃。

## 没做完的部分

| 方案书里的东西 | 状态 |
|---|---|
| 通知监听（主数据源） | 已实现，`NotifListener.java` |
| 无障碍读屏 | 已实现，但只做"用户点一下读当前屏"，没做自动上滑翻页 |
| 截图 OCR 兜底 | 未实现（会引入第三方识别库，需要联网/大包体，先留接口） |
| 第三级端侧大模型（1.5B/4bit） | **未接入**。当前用规则抽取替代，字段与提示词设计的输出结构一致 |
| 第二级小 BERT | **未接入**，当前是同结构的多分类逻辑回归（40KB 权重，端侧纯点积） |
| 后台排队调度（充电/空闲批处理） | 未实现，现在是常驻监听即时处理 |
| 日历写入 | 已实现（系统 Intent，无需额外权限） |
| 语音/图片消息 | 只按占位符处理 |

## 装到手机上

Android 7.0 或更新版本。只安装主 App 即可使用「离线演示」，无需打开通知读取或无障碍权限。

```bash
adb install -r android/build/nopalou.apk
# 可选：验证真实 Android 通知链路时安装回放器
adb install -r android/build/replay.apk
# 允许读通知
adb shell cmd notification allow_listener com.nopalou/com.nopalou.NotifListener
# 需要读屏时（可选）
adb shell settings put secure enabled_accessibility_services com.nopalou/com.nopalou.ReadService
```

打开主 App，点「离线演示」查看三种卡片，再点「播放群消息更新」看作业与考试改期、接龙已接后撤卡。退出演示即可回到日常卡片。

也可以从主界面点「粘贴群消息」。例如填群名「数据库系统」、发送者「王老师」，粘贴「明天 9:00 期中考试」及另起一行的地点。点卡片右侧「修正」可调整显示标题和时间，点卡片正文可回查原文或加入日历。

验证通知链路时，先填写档案（回放器使用演示身份），再打开通知使用权。点主 App 的「通知回放」或打开「消息回放器」，点「开始回放」，272 条消息会作为通知陆续发出。

本机自建 APK 默认使用新生成的调试密钥。覆盖安装已有版本时，需要使用同一签名，可在构建时传入 `--keystore`。

评委可以用 JDK 和 Node.js 在电脑上独立运行 `node eval/run_test.mjs Step12Test` 看离线演示逻辑，或运行 `Step16Test`、`Step17Test` 对照考试改期和清空行为。用例直接调用应用引擎。

在主界面点「到期提醒」可开启功能。Android 13 及以上需要另外允许本应用发通知。可用人工修正将一张未完成测试卡设为一小时后到期，再核对系统调度与通知内容。JVM 策略测试可运行 `node eval/run_test.mjs Step18Test`。
